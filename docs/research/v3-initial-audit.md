# OBA V3 initial engineering audit

Date: 2026-11-25. This is an in-progress audit, not a final release audit. Findings below are based on inspected source and commands in this session; specialist findings will be incorporated after review.

| Severity | Finding and evidence | Impact / remediation |
| --- | --- | --- |
| Critical, observed | The initial JDK 21 offline Maven test command failed at test compilation because `CliTest` referenced the absent `Main.publishNewFile` method. | The interrupted worktree could not build. Implement the tested publication behavior, rerun focused and full tests. |
| High, observed | `Main.rename` previously checked destination existence then used `Files.move(..., ATOMIC_MOVE, REPLACE_EXISTING)`. The Java 21 `Files.move` specification says that for `ATOMIC_MOVE` other options are ignored and replacement of an existing destination is implementation-specific. | A concurrently created destination could be overwritten after preflight. Publish staged files with an operation that refuses an existing name; test it and document filesystem support and crash limitations. [Java 21 Files API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/file/Files.html#move(java.nio.file.Path,java.nio.file.Path,java.nio.file.CopyOption...)). |
| High, source-inspected | `KeepRuleSet` had no production caller at audit time. | **Partially remediated:** the renamer and CLI now consume exact rules, and focused tests cover keep-overrides-selection and diagnostics. General rule configuration and broader compatibility remain open. |
| High, source-inspected | `AnalysisSnapshotCoordinator` has no production caller; it explicitly returns `mayAuthorizeRenaming() == false`. WALA and SootUp adapters do not participate in transformation decisions. | The mandatory libraries are present and operational in isolated analysis, but end-to-end integration is unproven. Build a scoped consumer with snapshot identity, explicit unknowns, invalidation and integration tests; do not treat agreement as proof. |
| High, source-inspected | The rename pass depends on an operator-supplied closed-world/name-sensitive-use assertion. It does not itself establish absence of reflective, configuration, native or external references; it currently rejects multi-release entries. | Treat the current pass as experimental and bounded. Implement conservative detection and policy/keep infrastructure, expand differential and compatibility fixtures, and do not claim general correctness. |
| Medium, source-inspected | `MISSION.md` and `AGENTS.md` were absent; older state descriptions did not cover all interrupted work. | Preserve requirements and a V3 evidence ledger, and update state after validated changes. |
| Medium, source-inspected | `AnalysisSnapshotCoordinator.inventory` used unbounded class-entry reads and bypassed archive limits. | **Partially remediated:** inventory now uses bounded `JarArchive` reads with an explicit-limits overload. The staging copy and whole-analysis working set still need resource budgets. |

Other scopes under active review include exact mapping completeness, archive/ZIP safety, MRJAR semantics, independent verification, test coverage, performance and licensing. The existence of tests or documentation is not yet evidence that those requirements are fully satisfied.

## Independent specialist reviews

- Transform reviewer (read-only, no tests): confirmed the lack of a keep-rule consumer at the time of review; identified peak archive-memory amplification from entry copies and the absence of a reusable production JVM verification gate. It recorded that compatibility remained a caller assertion, not an established fact. The keep-rule finding is now partially remediated; memory and runtime-gate work remain open.
- JVM/analysis reviewer (read-only, no tests): confirmed ASM's explicit hierarchy writer has focused generated-fixture coverage, but the WALA/SootUp coordinator has no consumer; its snapshot identity omits dependencies, runtime release and analysis configuration; both analysis adapters reject MRJAR variants; and coordinator ingestion has unbounded class reads. Its exact OBA V3 read receipts were reported separately, including workflow contracts, ASM frame guidance, WALA scope recipes and SootUp-to-ASM integration guidance. These reports were assessed against the current source; they are not independently reproduced test results.
- Licensing specialist: resolved the runtime Maven dependency tree in an isolated cache and reviewed versioned upstream POMs/license files. Its preliminary finding is that the unshaded project JAR does not embed runtime dependencies, while notices and distribution obligations still need an explicit inventory; a complete versioned inventory is pending. This is a technical review, not a legal opinion.

Archive copy amplification has since been partially remediated: owned entry arrays are shared across immutable snapshots and output verification streams bytes. This bounds retained archive payloads, not the complete renamer working set or caller-requested defensive copies. The independent specialist reports 10 focused tests passing; a shared full-suite run is pending.

### Follow-up review of the analysis-aware rename path

An independent read-only V3 specialist reviewed the current implementation after CLI integration. No unsafe authorization was demonstrated within the stated narrow scope. Remaining findings: snapshot identity contains hard-coded version labels and does not bind configurable dependencies or analysis options (medium); reflection sink coverage is intentionally incomplete and per-pattern tests are missing (medium); SootUp checks owner-level facts rather than exact selected-method identity (low); no end-to-end disagreement-veto fixture exists (low); and machine-readable reports are still missing (low). The reviewer ran no tests. These are scoped findings, not a final audit or proof of correctness.

### Independent forked-verifier review

The read-only reviewer identified missing input/child-memory bounds and unclear Java versions below the Java 21 helper baseline (high), mutable-path races between inspection, verification and publication (medium), lack of CLI dependency inputs (medium), and a mapping rollback race (low). The CLI dependency limitation is documented; resource limits, runtime diagnostics and file-identity handling require remediation. The rollback deletion has been removed to avoid deleting a replacement file; output failure after mapping publication may leave the mapping behind. The review did not run tests and is not the final audit.
